# Тест-кейсы для API

В этом документе описаны тест-кейсы, которые были автоматизированы в рамках данного проекта.

| ID      | Название                                    | Приоритет | Описание шагов                                                                                                                              | Ожидаемый результат                                                                                                                                                                     |
| :------ | :------------------------------------------ | :-------- | :------------------------------------------------------------------------------------------------------------------------------------------ | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TC-001  | **Получение сущности по ID**                 | High      | 1. Создать новую сущность через `POST /create`. <br> 2. Получить ID созданной сущности. <br> 3. Отправить `GET /get/{id}` с полученным ID.       | 1. Статус-код ответа `200 OK`. <br> 2. Тело ответа содержит данные созданной сущности. <br> 3. Поля `id`, `title`, `verified` в ответе соответствуют отправленным при создании.                |
| TC-002  | **Обновление данных сущности**              | Medium    | 1. Создать новую сущность. <br> 2. Подготовить новый payload с измененными данными (`title`, `verified` и др.). <br> 3. Отправить `PATCH /patch/{id}` с новым payload. <br> 4. Повторно запросить сущность через `GET /get/{id}`. | 1. Статус-код ответа на `PATCH` - `204 No Content`. <br> 2. Тело ответа на повторный `GET` содержит обновленные данные.                                                                       |
| TC-003  | **Проверка наличия сущности в общем списке** | Medium    | 1. Создать новую сущность. <br> 2. Отправить `GET /getAll`.                                                                                  | 1. Статус-код ответа `200 OK`. <br> 2. Список сущностей в теле ответа не пустой. <br> 3. ID созданной сущности присутствует в полученном списке.                                                |
| TC-004  | **Удаление сущности**                       | High      | 1. Создать новую сущность. <br> 2. Отправить `DELETE /delete/{id}`. <br> 3. Попробовать снова получить удаленную сущность через `GET /get/{id}`. | 1. Статус-код ответа на `DELETE` - `204 No Content`. <br> 2. Статус-код ответа на повторный `GET` - `404 Not Found`. <br> *(Примечание: из-за бага в API сейчас возвращается `500`)*       |
| TC-005  | **Фильтрация списка по заголовку**          | Medium    | 1. Создать новую сущность с уникальным заголовком. <br> 2. Отправить `GET /getAll` с query-параметром `title`, равным этому заголовку.          | 1. Статус-код ответа `200 OK`. <br> 2. Список сущностей в ответе не пустой. <br> 3. Все сущности в полученном списке имеют заголовок, соответствующий фильтру.                             |
